## F-1 wild-PC（aarch64 `ELR=0x0`）

- 描述：init 探针偶发故障家族的跳零分支。签名 `EL0 sync fault: pid=5 ESR=0x82000006 FAR=0x0 ELR=0x0 -> terminate` + `exit: pid=5 code=5`，三条运行时判据全缺（死在 `[THREAD] PASS` 之前）。乙取证轮（2026-11-05）判死三假设：SP 有效（栈指针未踩）、SPSR NZCV=0x6 是真实用户 PSTATE（非内核零帧 eret）、内核 `elr`/`lr` 写点造不出 `ELR=0 ∧ X30=0` 组合（维持不改写点）；落点钉在 `thread_probe` 的 `group_exit_leg` 内部。#128 丙后判（2026-11-07）：三候选中的第三条（aarch64 fork 无 COW 父子共享写）已随裁定 7 回判消失；**剩余两者（内核直写用户页的 SETTID/wait4 写回 vs 用户态自取空函数指针）之间的定论仍未做**。
- 方案：待授权取证改装后再钉。既有装备读数：#128 裁定⑥甲的一次性 `x29` 帧链 + 故障点栈上 8 字节采样已跑并出数即撤——帧链走不动（`x29=0x0`）、栈上采到可打印 ASCII 而非返回地址、采样轮该家族未再现 ⇒ 不足以定论。下一步候选：甲、更高命中率扰动下重采帧链/栈样（需先解决「采样轮不再现」——扰动源与采样同轮耦合）；乙、`group_exit_leg` fork 前后哨兵字定向复现（判死并发写 0 的写者）；丙、搁置（异常出口面已判死，剩余是内存语义面，等真实命中样本积累）。三选一待裁。

## F-2 NULL-copy（x86_64 `vec=14 err=0x4 cr2=0x0`）

- 描述：init 探针偶发故障家族的 NULL 源整块拷贝分支。签名 `[IDT] user exception: vec=14 err=0x4 rip=<memcpy rep movsb 内> cr2=0x0` + `exit: pid=5 code=5`；`err=0x4` = 用户态读缺失页，`cr2=0x0` = 源指针 NULL。历史三样本规模随宿主状态变（2103 次循环 / 2 次 / 1 次），`rip` 裸地址只按当次构建解释，跨样本比形态不比地址。**L-1（NULL 源 copy 的调用者）未定位**：需 `[IDT]` 行扩出 `rdi/rsi/rdx`（目的/源/长度）才能一次判死，属取证改装、待授权。**L-2（崩溃循环放大机制）预期已消**：R-4（`aarch64-reap-timeout-rootcause.md`）把 `exiting`/Zombie 从全部拣选/投送/重排面排除，「exit 返回用户态 / Zombie 再投送」链已修；修复后尚无本签名新样本（2026-11-10 纠察批跑的是 aarch64，非本签名的 x86_64 面），待 x86_64 压力轮确认循环不再放大。
- 方案：待授权取证改装（`[IDT]` 行扩 `rdi/rsi/rdx`，沿用 §6③a「锁外发射」纪律）+ x86_64 高负载定向复现；命中后按 rsi=0 的调用点归因 L-1。L-2 确认腿可复用既有 `[REDISPATCH]` 七站点取证（#129 甲）：修复后健康启动命中 0 属预期，若仍见同 pid `exit:` 重复则按 `via=` 归类新形态。本轮不改装、不施工。
