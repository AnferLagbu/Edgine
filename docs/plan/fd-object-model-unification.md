# fd 对象模型统一工程（per-process fd 表接管全局 FdPlan）

描述：终态目标——消除"全局 FD 编号 + 子系统基址分段"过渡设计。当前 8 个非 VFS 子系统（Smoltcp/UDS/EventFd/SignalFd/Inotify/TimerFd/PidFd/UserFaultFd）的 fd 由全局位图分配、fd 数值全局有效且与进程无关：任何进程可引用任何其他进程的 socket fd（I3/I4 类边界松动），dup2 到 socket、CLOEXEC、进程退出回收均缺失。终态采用 Linux `file_operations` / Asterinas `File` trait 同构设计：引入与文件系统解耦的统一 fd 对象 trait（read/write/poll/ioctl/release），全部对象注册进 per-process `FdTable` → `OpenFileTable`，`FdPlan`/`FdSubsystem`/`subsystem_of`/`idx_of` 整体退役，fd 分发按对象能力（`Arc<dyn File>` 动态分发）而非数值区间。
方案：分四阶段（各自独立 PR 序列，达成 §2.3 六门槛）：
1. [X] 设计立场先行：新增 `docs/design/fd-object-model-design.md`——trait 方法集、poll 事件模型（与 P4/D8b 衔接）、与 `Inode` trait 的关系（叠加 `File` 层 vs `OpenFile` 双持有）、fork/dup/exec 语义矩阵。
2. [X] 抽象落地：`functions::fs` 引入 fd 对象 trait；`OpenFile` 与 Inode 解耦（socket/eventfd 等非文件对象进入 `OpenFileTable`）；VFS fd 迁移至统一分发点（read/write/close/poll 单入口）。
   详情：2026-11-10 按用户裁定「B 相对完整：方法全部接入 VFS 消费面」单批收口。新建 `functions/fs/file.rs`（`File` trait + `PollEvents`（Linux `<poll.h>` 位值）+ `RegularFile` 薄适配器）；`OpenFile` 改持 `Arc<dyn File>`，`file_type` 由对象派生，目录/元数据操作经 `as_inode()` 桥接；VFS 消费面接入：read（`read_forward` 优先）、write/pread/pwrite（`read_at`/`write_at`）、lseek（`stream()` 判 ESPIPE）、fstat/fchmod/fchown/truncate/readdir（`as_inode()`）、poll（`File::poll` 快照，每 fd 至多计一次 ready）、ioctl（`File::io_control`，`NotSupported` 回落终端策略）；管道端点 `PipeEndpointInode` 实现 `File`（含 `read_forward`/`stream`）；`OpenFileTable::dec_ref` 在表锁外触发 `File::release`，并修正归零判据（`dec_ref()` 返回减前值，最后一个引用判据为 `== 1`，原 `== 0` 使槽位永不回收）。epoll/`VfsPollPolicy`、8 个非 VFS 子系统、`FdPlan`/`subsystem_of`/`sm_slot` 按裁定不动（阶段 3/4）。
3. [ ] 子系统迁移：8 个非 VFS 子系统逐个把槽位注册改为 fd 对象挂表（每个子系统一个 PR + 回归测试）；全局位图分配器随最后一个子系统迁移后删除。
   详情：2026-11-10 第 1/8 个子系统 **EventFd 已收口**。删除 `privileged/syscall/eventfd.rs`（EFD_TABLE / EFD_MAX_SLOTS=16 / 位图分配 / `EFD_FD_BASE`），新建 `functions/fs/eventfd.rs`（fd 对象实现归 `functions::fs`，与 `inotify`/`pipe_fd` 同构；同时避免 `sync → fs` 新有向边构成 `fs ↔ sync` 禁用环）：`EventFdFile` 实现 `File`（read_at/write_at/poll/stream/io_control/file_type），不实现 `Inode`（`as_inode()==None` 作为"非 inode 特殊对象"统一判据）；创建路径 `OpenFile::from_file` → `OPEN_FILE_TABLE.alloc` → per-process `FdTable::alloc_fd(handle_id, cloexec)`。分发面收口：`io.rs` 删除 eventfd 数值分支，写循环对特殊对象短写即停（`vfs_is_special_fd`）；`handle.rs` 读写后唤醒判据泛化为 `fd_event_may_change`（管道 ∪ 非 inode 对象）、fstat 对特殊对象合成 stat；epoll `check_fd_ready` 新增 `VfsOps::fd_poll_special` 对象级 poll（替代 eventfd 数值分支）；`sendfile` 改按 `as_inode()` 排除。顺带修复三个预存缺陷：eventfd `close(2)` 不回收槽位、`dup(eventfd)` 恒 EBADF、eventfd 写不唤醒 epoll。契约测试 `td04_stale_fd_test` / `td15_fd_idx_of_test` / `fd_allocator_unified_test` 同步改写，`fd_object_model_test` 追加对象行为与源码形状锁; 对象级内核测试用例落 `kernel_tests/test_eventfd.rs` (functions 层不残留"仅 kernel_test"门控, E-03)。2026-11-10 第 2/8 个子系统 **SignalFd 已收口**。删除 `privileged/syscall/signalfd.rs`（SFD_TABLE / 全局位图槽位 / `is_signalfd_fd` 数值分派 / 裸指针用户掩码读写）与 `functions/sync/signalfd.rs` 死代理，新建 `functions/fs/signalfd.rs`：`SignalFdFile` 实现 `File`（`read_at` 取 `pending & sigmask` 最低编号信号、消费并写 128 字节 `signalfd_siginfo`，无信号 → EAGAIN；`write_at` → EINVAL；`poll`；`io_control`；`stream` → ESPIPE；`file_type`），不实现 `Inode`；PID 绑定语义保留（read/poll 仅对创建进程生效，fork 继承的 fd 在子进程按无效 fd 报 EBADF/ERR），SIGKILL/SIGSTOP 过滤保留。创建/改掩码：`fd == -1` 走 `OpenFile::from_file` → `OPEN_FILE_TABLE.alloc` → per-process `FdTable::alloc_fd(handle_id, cloexec)`；`fd >= 0` 经 `File::io_control(SFD_IOC_SETMASK)` 回访对象私有掩码（辅助 syscall 反向访问模式，不改 `File` trait）。syscall 拆为 `signalfd_syscall`（经 privileged `read_struct_from_user` 读用户 u128 掩码，I4 校验 + 非对齐安全）与 `signalfd_apply`（不触用户内存，host 侧可直接驱动全链）。掩码内部收窄 u64（pending 位图本就 u64，bit 64-127 无对应 pending 信号；SIMPLIFIED 标注）。分发面收口：`io.rs` / `epoll.rs` 删除 signalfd 数值分支，`sendfile` 删除 220..236 区间，`dispatch.rs` 改指对象实现，`privileged/syscall/mod.rs` 与 `privileged/tests/mod.rs` 摘除旧模块/注册点。顺带修复：close 路径统一走 VFS 通用回收（旧全局槽位无 close 入口，槽位泄漏）、向 signalfd 写由误报 EBADF 改为 EINVAL、短缓冲读 EINVAL 防溢出、用户掩码读取纳入 I4 安全代理。契约测试 `td04_stale_fd_test` / `td15_fd_idx_of_test` / `fd_allocator_unified_test` 同步收缩，`fd_object_model_test` 追加三组 signalfd 行为/创建路径/分发点锁；对象级内核测试落 `kernel_tests/test_signalfd.rs`。余 6 个（Smoltcp/UDS/Inotify/TimerFd/PidFd/UserFaultFd）按每个一 PR 继续。
